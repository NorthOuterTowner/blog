# 用分箱中位数和 MAD 阈值剔除曲线上的散点

最近在处理一批测量数据：每条曲线 8192 个采样点，整体有斜率，末端还会压缩饱和，中间零星混着一些突高突低的散点。这些散点会把后续的峰值查找和统计量整体带偏，得先剔掉。第一反应是"算个均值和标准差，超过 3 sigma 的删掉"，实际跑下来完全没用——离群点自己就把均值和标准差拉走了。本文记录一套更稳的做法：按 x 分箱取中位数当趋势线，用残差的 MAD 做阈值，迭代两轮；以及这套方法在局部污染率过半时会怎么失效、怎么补。不涉及聚类类方法（DBSCAN 那条路单独一篇）。

## 为什么不能用均值 + 标准差

均值和标准差的崩溃点（breakdown point）是 0：只要有一个足够极端的点，估计值就能被拉到任意远。后果是阈值本身被离群点撑大，于是离群点落在阈值内，看起来"符合分布"。这个现象叫**掩蔽效应**（masking）。

替代品是中位数和 MAD：

| 统计量 | 崩溃点 | 说明 |
| --- | --- | --- |
| 均值 / 标准差 | 0% | 一个极端点就失效 |
| 中位数 / MAD | 50% | 污染不超过一半时仍然可用 |

MAD 全称 median absolute deviation，定义是 `median(|x - median(x)|)`。它的量纲和数据一致，但数值比标准差小，对正态分布来说需要乘一个换算系数才能当 sigma 用：

```py
mad = 1.4826 * np.median(np.abs(res - np.median(res)))
```

1.4826 就是 `1 / Φ⁻¹(0.75)`，把 MAD 换算成正态分布下的 sigma。乘上这个系数之后，阈值 `k * mad` 里的 k 才能按"多少个 sigma"来直觉理解，常用 3~5。

## 整体流程

曲线本身有斜率，所以不能直接对 y 做统计——曲线形状贡献的离散度远大于噪声。得先把"趋势"和"残差"分开：

1. 按 x 分箱，每箱内取 y 的中位数，得到一串 `(bin_center, median)`。
2. 线性插值成逐点趋势线 `trend`。
3. 残差 `res = y - trend`。
4. 算残差的中位数和 MAD，剔除 `|res - center| > k * mad` 的点。
5. 用剩下的内点重新估趋势线，回到第 1 步，共两轮。

第 5 步的迭代是必要的：第一轮的趋势线本身受离群点影响（每箱的中位数会被轻微拉动），用第一轮筛出的内点重算，趋势线会更贴主体。两轮基本收敛，再迭代收益很小。

## 实现

```py
import numpy as np


def robust_trend_mask(x, y, n_bins=64, k=4.0, n_iter=2):
    x = np.asarray(x, dtype=float)
    y = np.asarray(y, dtype=float)
    mask = np.isfinite(x) & np.isfinite(y)

    lo, hi = np.min(x[mask]), np.max(x[mask])
    edges = np.linspace(lo, hi, n_bins + 1)

    trend = np.zeros_like(y)
    for _ in range(n_iter):
        x_fit, y_fit = x[mask], y[mask]
        idx = np.clip(np.digitize(x_fit, edges) - 1, 0, n_bins - 1)

        centers, medians = [], []
        for b in range(n_bins):
            sel = idx == b
            if np.count_nonzero(sel) < 3:
                continue
            centers.append(0.5 * (edges[b] + edges[b + 1]))
            medians.append(np.median(y_fit[sel]))
        if len(centers) < 2:
            break

        trend = np.interp(x, centers, medians)
        res = y - trend

        center = np.median(res[mask])
        mad = 1.4826 * np.median(np.abs(res[mask] - center))
        if not np.isfinite(mad) or mad <= 0:
            break                      # 数据全同值，再算下去阈值为 0 会删光
        mask &= np.abs(res - center) <= k * mad

    return mask, trend
```

两个防御点值得单独说：

- `mad <= 0` 必须 break。数据全是同一个值时 MAD 为 0，阈值 `k * 0 = 0`，下一句会把所有点都判成离群，直接清空数据。
- 每箱点数太少（`< 3`）就跳过这一箱，别用一两个点的"中位数"当趋势，否则趋势线会在稀疏区剧烈抖动。

相比 DBSCAN 这类聚类方法，这套流程的优势是可控：只有一个直觉参数 k，复杂度 O(n log n)，结果确定可复现，也不受采样密度不均的影响。工程上应该先上这个，聚类方法只在"要剔掉整条离群带子"这种密度方法才擅长的场景补一刀。

## 多通道共享采样时掩码要按位与

同一批采样往往同时记了几个物理量（比如增益和相位），它们共享同一个 x。这时候对每个通道各自算掩码，最后按位与：

```py
mask = mask_gain & mask_phase
```

任一通道离群就丢掉整个采样点。这么做是为了保证下游各列长度一致——如果各通道独立删各自的点，列长就对不上了，后面无论存文件还是画图都得额外对齐。

## 别真的删元素，写 NaN

掩码算出来之后，处理方式有两种：删掉数组元素，或者把被剔除的位置写成 NaN。选后者：

- 列式二进制存储（比如把多条曲线堆成 npz 里的二维数组）要求各行等长。删元素之后每条曲线长度不同，就成了不规则数组，存不进去。
- NaN 保住了数组形状，matplotlib 的 `plot` / `scatter` 遇到 NaN 会自动跳过，画图不用改。

代价是下游所有聚合调用都得换成 nan-aware 版本，这个坑单独记了一篇（`../python/basic/numpy-nan-pitfalls.md`）。

## 效果不要用 std 来度量

清理前后对比标准差是没用的：曲线本身的形状就贡献了大部分离散度。实测清理后某个通道的 std 反而从 1.09 升到 1.12——因为删掉的点集中在曲线两端，剩下的样本分布变了。

该看的是两个量：

- **趋势残差的 sigma**：本例相位通道从 1.52 降到 1.21。
- **残差超过 5 sigma 的点数**：从 376 降到 0。

这两个指标只反映"点相对趋势线的偏离"，与曲线形状无关，才是清洗想改善的东西。

## 局部污染过半时，中位数趋势线会被劫持

上面那套跑起来之后遇到一个奇怪的现象：绝大部分离群点都剔干净了，但某个 x 区间里剩下一小撮明显离群的点，怎么调 k 都删不掉。调小 k 只会开始误删主体，那一撮依然在。

### 诊断：把趋势值打出来

有效的诊断手法是打印**残留点所在位置的趋势值**，和该处主体的中位数对比：

```text
残留点 x≈4.2  trend=68~74   该处主体中位数=14   残差=1~5
```

趋势线自己爬到离群带子上去了。残差只有 1~5，任何合理阈值都会判它是正常点。到这一步就清楚了：问题出在基准线，不在阈值。

### 根因：崩溃点是 50%，而这里说的是局部

中位数的崩溃点是 50%，这个数字通常被当成"很安全"来理解。但分箱之后，约束的对象变成了**每个箱内部的污染率**。实测出问题的那几个箱污染率是 42%~47%——已经贴着崩溃点，中位数开始朝离群群体滑动。全局污染率只有百分之几，完全看不出来。

一般化的教训：稳健估计器的保证是针对它实际作用的那个样本集合的。任何 per-bin、滑窗、分组的稳健统计，真正的约束都是**局部污染率**，而局部污染率可以远高于全局。

### 解法：给趋势线加一层跨箱中值滤波

被污染的箱通常是少数且连续的（离群带子只覆盖一段 x）。那就在"各箱中位数"这条序列上再做一次中值滤波，用相邻正常箱把被劫持的箱压回去：

```py
medians = _median_filter(np.asarray(medians), 9)   # 关键的一行
trend = np.interp(x, centers, medians)
```

窗口取 9。前提是被污染的箱数少于窗口的一半，本例污染 4~5 箱，刚好压住。窗口太大会把曲线本身的弯曲抹平，太小压不住污染，需要按"离群带子横跨多少个箱"来定。

加上这一行之后，原来漏剔的那一撮全部归零。这也反过来确认了症状出在趋势估计而不是后面的阈值步骤。

## 小结

排查这类清洗问题的顺序是**先查基准线，再查阈值**。阈值调不动的时候，大概率是基准线已经错了，继续调参只会一边误删一边漏剔。

方法选择上：分箱中位数 + MAD 处理"个别散点"足够好且可控；遇到成片的、局部占比过半的离群结构，它需要额外的跨箱平滑，或者换成利用连续性先验的方法。
