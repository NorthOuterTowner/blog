# 让程序化的鼠标移动看起来像人手

写完用 `SendInput` 控制鼠标的底层部分之后，遇到一个更有意思的问题：怎么让这些移动看起来不像机器干的。第一版是直线匀速移动到目标点，肉眼一看就知道是脚本——真人的鼠标轨迹既不是直线，速度也不均匀，而且移动同样距离花的时间还不一样。

这其实是个运动学建模问题，人机交互领域研究得很透。本文记录三个关键模型：路径用三次贝塞尔、速度用最小急动度（minimum-jerk）时间重映射、时长用 Fitts 定律，以及一堆让整体分布更像人的细节。不涉及底层的 API 调用，那部分在 `../python/basic/ctypes-win32-input.md`。

## 三件事缺一个都会露馅

| 维度 | 机器的样子 | 人的样子 | 用什么建模 |
| --- | --- | --- | --- |
| 路径 | 直线 | 略带弧度的曲线 | 三次贝塞尔 |
| 速度 | 匀速 | 钟形速度曲线，先加速后减速 | minimum-jerk 时间重映射 |
| 时长 | 常数或距离的线性函数 | 随距离对数增长，且有随机 | Fitts 定律 |

三个维度是独立的，只做其中一个改进有限。直线加上钟形速度还是直线；曲线加匀速看着像动画补间。

## 路径：三次贝塞尔

人手做定点移动时，肩肘腕的复合运动会让轨迹带一点弧度，弧的方向和大小随机。用三次贝塞尔曲线模拟：起点终点固定，两个控制点在路径两侧随机偏移。

```py
import random, math


def bezier_control_points(p0, p3):
    x0, y0 = p0
    x3, y3 = p3
    dx, dy = x3 - x0, y3 - y0
    dist = math.hypot(dx, dy)
    if dist < 1e-6:
        return p0, p3

    nx, ny = -dy / dist, dx / dist        # 垂直于移动方向的单位向量
    bow = random.uniform(-0.18, 0.18) * dist

    pts = []
    for frac in (random.uniform(0.20, 0.40), random.uniform(0.60, 0.80)):
        bx = x0 + dx * frac + nx * bow * math.sin(frac * math.pi)
        by = y0 + dy * frac + ny * bow * math.sin(frac * math.pi)
        pts.append((bx, by))
    return pts[0], pts[1]
```

两个设计点：

- 控制点的位置分别取在 20%~40% 和 60%~80% 处，而不是固定的 1/3、2/3。固定位置会让所有轨迹的弧形一个模样。
- 偏移量乘 `sin(frac * pi)`。这个因子在两端趋于 0、中段最大，效果是**轨迹两端贴住起点终点方向，中间弓最开**。不乘的话起点处就会横向偏出去，看着像手抖了一下才出发。

`bow` 的符号随机，所以弧可能朝任意一侧弯。幅度取距离的 ±18% 是试出来的，再大就像在画圈了。

## 速度：最小急动度时间重映射

贝塞尔曲线的参数 t 线性推进的话，速度还是接近匀速的。要得到人手的速度曲线，得对 t 做一次非线性映射。

**最小急动度**（minimum jerk）是运动控制里的经典模型：假设人在做定点移动时，会选择让"加速度的变化率（jerk）的平方积分"最小的那条轨迹。解出来是一个五次多项式：

```py
def minimum_jerk(t):
    return 10 * t ** 3 - 15 * t ** 4 + 6 * t ** 5
```

这个函数满足 `f(0)=0`、`f(1)=1`，而且**两端的一阶和二阶导数都是 0**——起步和停止都是平滑的，没有速度突变。求导得到的速度曲线是钟形的，和实测的人手速度曲线吻合得很好。这是它比 ease-in-out 之类的插值函数更可信的原因：它不是拍出来的曲线，是从一个物理假设推出来的。

用法是把它的输出喂给贝塞尔的参数：

```py
def step(p0, p1, p2, p3, elapsed, duration):
    t = min(1.0, elapsed / duration)
    return bezier(p0, p1, p2, p3, minimum_jerk(t))    # 注意是 minimum_jerk(t) 不是 t
```

容易写错的地方就在这里：`minimum_jerk` 是作用在**时间参数**上的，不是作用在坐标上。位置由贝塞尔决定，速度由时间映射决定，两者正交。

## 时长：Fitts 定律

移动时长不该是常数，也不该和距离成正比。Fitts 定律说的是定点移动的时间随"距离/目标宽度"的**对数**增长：

```py
def move_duration(dist):
    base = 0.28 + 0.16 * math.log2(1 + dist / 40.0)
    return base * random.uniform(0.8, 1.4)
```

对数的直觉解释是：移动过程是"粗定位 + 若干次减半修正"，每次修正把剩余距离减半，所以次数随距离对数增长。实际表现就是短距离移动不会快得离谱（有个 0.28 秒的基线），长距离移动也不会慢得离谱。

后面乘的 `uniform(0.8, 1.4)` 是必须的。人不会两次用一样的时间走同一段距离，时长本身也得是随机变量。区间不对称（下界 0.8 上界 1.4）是因为人偶尔会"慢一下"，但很少快过自己的基线速度。

## 让整体分布更像人的细节

单次移动做对了，连续跑一段时间还是可能露馅——因为宏观分布不对。补几个：

**每步叠一点手抖**：每个中间点加一个 σ=1 像素的高斯噪声。人手在移动中有生理性的微颤，完全平滑的曲线反而不自然。

**过冲与修正**：25% 的概率在到位后再往前过冲几个像素，然后小幅回退到目标。这是人手的二次修正行为——快速移动很难一次停准。

**原地微抖**：20% 的概率不做位移，只在当前位置附近抖几个像素。对应"手搭在鼠标上但没打算移动"的状态。

**双尺度的停顿分布**：停顿时长不能用单一分布。人的行为是"密集操作一阵，然后走神很久"：

```py
def pause_duration():
    if random.random() < 0.12:
        return random.uniform(8.0, 40.0)     # 长停顿：走神、看别处
    return random.uniform(0.4, 3.0)          # 短停顿：连续操作之间
```

12% 的长停顿概率是关键。只用短停顿的话，累积起来的操作密度远高于真人。

**落点分布也要分尺度**：

```py
def next_target(cur, desktop):
    if random.random() < 0.75:
        r = random.uniform(40, 320)          # 近距离：在当前区域内操作
        a = random.uniform(0, 2 * math.pi)
        return clamp(cur[0] + r * math.cos(a), cur[1] + r * math.sin(a), desktop)
    return random_point(desktop)             # 25%：跨屏大跳，切换窗口
```

真人的鼠标位置有很强的局部性——大部分时间在一个小区域里操作，偶尔大幅跳到另一个窗口。均匀随机撒点的话，轨迹会均匀铺满整个屏幕，这个特征本身就很反常。

## 调参技巧：固定随机种子

这套东西全是随机数，改一个参数之后很难判断效果是变好了还是抽到了不同的随机数。给脚本加一个 `--seed`：

```py
parser.add_argument('--seed', type=int, default=None)
...
if args.seed is not None:
    random.seed(args.seed)
```

固定种子之后轨迹完全可复现，改 `bow` 的范围或者 Fitts 的系数，可以画出改前改后的两条轨迹直接对比。没有这个开关的话，调参基本是在盲猜。

## 小结

"看起来像人"这个需求拆开之后是三个独立的建模问题，而且每个都有现成的模型可用：路径找几何插值、速度找运动控制理论、时长找人机交互定律。比自己拍一堆随机数靠谱得多——minimum-jerk 之所以有效，就是因为它来自一个关于人如何运动的假设，而不是"看着挺平滑"。

剩下一半工作量在宏观分布上：停顿、落点、行为模式的分布对不对，往往比单次移动的细节更容易暴露。判断标准是把长时间运行的轨迹和位置分布画出来，看它和真人操作的记录像不像，而不只是看单次移动的动画。
