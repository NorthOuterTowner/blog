# 用 DBSCAN 剔曲线离群点：别在原始坐标空间跑

处理一批测量曲线时遇到一种特殊的脏数据：除了零星的突高突低散点，还有**一整条平行飘着的带子**——一批采样点整体偏移了一个固定量，形状和主曲线完全一样。逐点阈值法对它无能为力（带子内部很紧密，相对自己的趋势线没有残差），所以想到用密度聚类：带子和主曲线之间有空隙，DBSCAN 应该能把它们分成两个簇，然后只保留主簇。

思路没错，但第一版直接把归一化后的 `(x, y)` 丢进 DBSCAN，结果带子确实删掉了，同时把最关心的那段数据也删掉了。本文记录这个坑的根因，以及正确的做法：**换聚类坐标，在趋势残差空间里聚类**。顺带记两个配套细节：归一化用 MAD 而不是分位跨度，以及效果怎么度量。

## DBSCAN 的隐含前提：簇内密度大致均匀

DBSCAN 的两个参数 `eps`（邻域半径）和 `min_samples`（核心点所需邻居数）共同定义了一个**全局的密度门槛**：eps 半径内邻居数达不到 min_samples 的点就是噪声。

这意味着它假设"同一个簇内部密度差不多"。这个假设在点云、地理坐标这类场景成立，但在**曲线**上不一定：

- 曲线在 x 方向的采样密度往往天然不均。本例末端进入压缩饱和区，同样的 x 步进对应的 y 变化变小、点数也少，那一段就是稀疏的。
- 单一 eps 无法同时适配密集段和稀疏段。调大了带子和主曲线连成一片，调小了稀疏段全成噪声。

## 踩坑：稀疏段被整段判成噪声

第一版的写法：

```py
from sklearn.cluster import DBSCAN

xy = np.column_stack([normalize(x), normalize(y)])
labels = DBSCAN(eps=0.05, min_samples=10).fit_predict(xy)
mask = labels == largest_cluster_label(labels)
```

结果：

```text
带子:      已剔除
曲线末端:  整段被判成噪声，一起删掉
峰值:      52.48  ->  43.43
```

峰值是这份数据里最关心的量，恰好落在被删掉的那一段。灾难性的失败，而且从图上不容易看出来——删掉之后曲线看起来还挺"干净"。

根因就是上一节说的：末端那段的局部密度低于 `eps=0.05 / min_samples=10` 定义的门槛，DBSCAN 按定义就该把它标成噪声。参数没写错，是**坐标空间选错了**。

## 解法：在趋势残差空间聚类

关键转换：先算一条稳健的趋势线，聚类的输入换成**残差**而不是原始 y。

```py
res_y = y - binned_median_trend(x, y)   # 主曲线整体塌到 0 附近
mask, labels = dbscan_mask([res_y, res_phase], eps=0.5, min_samples=10,
                           scale='mad', keep_clusters=1)
```

`binned_median_trend` 就是分箱中位数插值出来的稳健趋势线（做法见 `robust-trend-mad.md`）。

换空间之后性质完全变了：

| | 原始 (x, y) 空间 | 残差空间 |
| --- | --- | --- |
| 主曲线 | 沿 x 展开，密度随位置变化 | 全部塌到 0 附近，密度均匀 |
| 平行带子 | 与主曲线平行的另一条线 | 残差恒为 +N 的一团，明显离群 |
| 稀疏段 | 密度低，被误判 | 和其他段一样落在 0 附近 |

主曲线在整个 x 范围内密度均匀，DBSCAN 的前提这才成立。带子的残差是一个恒定的偏移量，独立成簇。孤立散点残差大且互相不聚集，直接是噪声。

改完之后 6 个测试频点的峰值全部保持原值，带子残留 0。

注意残差空间里可以不带 x 这一维——如果只想按"偏离趋势多少"分簇，把多个通道的残差堆成特征向量就够了。上面的例子用了两个通道的残差（增益和相位），这样"只在相位方向离群"的点也能被抓出来。

## 归一化要用 MAD，不要用分位跨度

聚类前要把各维归一化到可比的尺度，否则 eps 对不同维度含义不同。常见做法是用 1%~99% 分位跨度缩放，这里不行：

带子可能占到十几个百分点。1% 和 99% 分位会被带子撑开，跨度整体变大，归一化之后主体被压成很小的一团，eps 失去物理含义——同一个 eps 值在污染多的数据里对应更宽的实际范围，参数不可迁移。

用 MAD：

```py
scale = 1.4826 * np.median(np.abs(v - np.median(v)))
v_norm = (v - np.median(v)) / scale
```

MAD 的崩溃点是 50%，十几个百分点的污染撼动不了它。归一化之后 **eps 的单位就是 sigma**，取 0.3~1.0 之间，含义明确、跨数据集可复现。

## 兜底：全判噪声时返回全保留

参数过严时 DBSCAN 可能把所有点都标成 -1。这时候不能按"保留最大簇"的逻辑走下去，那会返回一个空掩码，等于把整份数据丢掉：

```py
if not np.any(labels >= 0):
    return np.ones(n, dtype=bool), labels    # 全保留，而不是清空
```

清洗类操作的默认失败方向应该是"什么都不做"，不是"什么都删"。一次误操作丢掉整份原始数据是不可接受的，漏剔只是效果差一点。

## 效果度量：别看 std

用标准差衡量清洗效果会得到误导性的结论。实测清理后某通道的 std 反而从 1.09 升到 1.12，因为曲线本身的形状贡献了大部分离散度，删掉两端的点改变了样本分布。

该看的是：

- 趋势残差的 sigma：相位通道 1.52 -> 1.21。
- 残差超过 5 sigma 的点数：376 -> 0。
- 关键物理量有没有被动过：本例是各频点的峰值，逐个对比清理前后是否相等。

最后这条最重要。它是对"有没有误删"的直接检验，比任何统计指标都硬。

## 小结

DBSCAN 在曲线离群剔除里的定位是**补刀，不是主力**：

- 主力用分箱中位数 + MAD 阈值，参数少、可控、不受密度不均影响。
- DBSCAN 只用来处理"成片的平行离群结构"这种逐点阈值法搞不定的情况，而且必须在残差空间跑。

更一般的教训：密度类算法失败时，先怀疑坐标空间的选择，再怀疑参数。参数是在给定空间里调，空间错了怎么调都有一边是错的。
